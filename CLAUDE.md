# Salon1cAPI

Unofficial Swift client for the 1С:SPA-Салон API (редакция 3.0), generated with
[swift-openapi-generator](https://github.com/apple/swift-openapi-generator). Sibling of
`YandexDeliveryExpressAPI` and `YooMoneyAPIClient` — same shape, same rules.

## Rules specific to this repository

1. **Fix spec problems as patches, not in Swift.** `openapi.yaml` is generated: the
   vendored `api_salon1c.yaml` + `apply-patches.sh`. Never edit upstream files or the
   output; a shape correction is a commented `# Pn` block. A hand-written extension that
   works around a generated shape is a workaround with a fixable root cause.
2. **Never edit generated code, and never commit the OpenAPI generator's output.**
   `Operations+Payload.generated.swift` is *our* derived artifact — committed like
   `openapi.yaml`, regenerated by `Scripts/generate-facade.sh`, never hand-edited.
3. **`nameOverrides` is unsafe here.** Broken for operations, and for schemas it leaks
   into unrelated property names — patch the document instead (`P1` for operationIds,
   `P7` for the `cart`/`Cart` collision). Write-up in
   `../YooMoneyAPIClient/Upstream/nameoverrides-verbatim-casing.md`.
4. **Platform floor is iOS 17 / macOS 14 / tvOS 17 / watchOS 10 / visionOS 1.** No
   `@available` annotations belong in this package.
5. **Swift Testing, not XCTest.** `#expect` by default, `#require` when later lines depend
   on the value, tags for selection.
6. **Errors are three channels here.** Documented non-2xx statuses (rare: 201/400 in the
   PascalCase dialect) are enum cases; transport/decoding failures are thrown `ClientError`;
   and `errors.code ≠ 0` inside a 200 body is a domain refusal that surfaces **as data** in
   0.1 — do not silently collapse any of the three. The opt-in `payload()` facade
   folds the first and third channels into `Salon1cError` with one case each
   (`.status`, `.refused`) — transport failures stay `ClientError` — so the
   distinction survives the throw.
7. **The six envelope dialects are per-op fidelity, never normalize.** Lowercase
   `{parameters, errors}`, PascalCase `{Parameters, Errors, Meta}`, singular `Error`,
   the `Request_id` hybrid, bare `{Result}`, and `errors`-inside-`parameters` are
   different wire shapes on different operation families — the map lives in
   `SpecOwnership`. A "consistency" fix is a spec bug.
8. **`apikey`/`usertoken` are literal-lowercase header names.** Header behaviour lives only
   in `AuthMiddleware`; nowhere else sets headers.
9. **Wire spellings stay.** `visites`, `finished_visites`, `salon_id`-less v2 paths — the
   document keeps what the API serves; `operationId` gets the proper name.
10. **Reference a debt item from code** as `// TODO(TD-n): …`.
11. **Everything lands via PR.** `main` is protected; Devin Review runs on push and
    `REVIEW.md` steers it. No AI attribution in commit messages or PR descriptions.
    Before merging, `contrib in laconicman/Salon1c --pr N` must read `owed 0` and
    `to re-read 0`: inline findings get in-thread replies (a summary comment is not
    a reply), review bodies get `contrib ack --with commit:…|comment:…|none:"…"`.
12. **Documented behaviour is the contract until the wire disagrees.** There is no test
    credential yet; where a document contradicts itself — or the vendor YAML and the
    .apib contradict each other — the patch picks a shape and the conflict is a `TD-n`,
    not a silent choice. Once live calls exist: replicate wire behaviour that works;
    change it only on evidence.

## Author's standing preferences

Clarity over brevity. Prefer a vetted SPM over hand-rolling when the dependency is smaller
than the problem — and say so explicitly when it is *not*. Cite sources in prose and in code
comments. DRY, separation of concerns, low coupling / high cohesion are the three that get
checked first.
